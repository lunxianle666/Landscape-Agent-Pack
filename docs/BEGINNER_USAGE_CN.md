# Landscape Agent Pack 小白使用手册

安装完成以后，怎么真正用 AI 画景观 CAD / SketchUp

你只需要会 AutoCAD / SketchUp 的基本操作，并能向 AI 说明要求。不需要先学 Python、MCP 或 COM。如果还没安装，先看[安装教程](INSTALL_WINDOWS.md)或复制[AI安装与配置总指令](AI_INSTALL_ASSISTANT_CN.md)。日常绘图不需要重复发送安装总提示词。

> 当前为 Release Candidate。模型空间 DWG 是重点；Layout / PDF / 截图、部分 Dimension 和不同 AutoCAD 版本仍可能有兼容问题。模型空间已正确时，优先保存结果，不要为了自动出图长时间调试。SketchUp 是可选 / Experimental，当前 RC 未完成运行时测试。

## 你负责想法，AI和Agent负责实现

直接描述：“我要做一个30×20m校园口袋公园，南侧主入口，中央休息区，北侧廊架，绿地率不低于45%。”不需要研究MCP Tool名称，也不用告诉AI“调用create_polyline”。

AI理解 → 设计 → 确定参数 → 你确认方案 → Agent执行 → 检查 → 按反馈修改 → 验收。

在一个支持本机工具的客户端里，这些职责可以连续完成。你负责设计意图与最终选择，不必把AI和Agent分成两个软件；AI给方案，Agent按本Pack规则操作。具体分工见[项目工作原理](HOW_IT_WORKS_CN.md)。

### 每天正常使用

1. 打开AutoCAD。
2. 打开支持本地MCP的Agent，例如符合条件的Codex / TRAE。
3. 让AI确认本Pack规则可读取、软件工具可用。
4. 直接说“我想做……”，提供场地、要求和不能动的内容。
5. AI先设计，你确认主要方案。
6. Agent在授权副本中执行，不修改唯一正式文件。
7. AI检查实际图纸与保存结果，你核对主要尺寸。
8. 继续提修改意见，例如“休息区感觉太小，帮我扩大一点，但不要减少太多绿地”。AI先说明调整范围与面积影响，再继续执行和验收。

这是用户参与、反复迭代的设计过程，不把一次生成当作最终作业。常规次要参数可以提出假设；真实边界、正式尺寸或冻结对象的变化需要确认。

## 1. 每天使用前要打开什么

1. 打开 AutoCAD。
2. 打开已配置本地 MCP 的 AI Agent，例如 Codex、TRAE 或其他支持本地工具的 Agent。
3. 在 AI 的输入框里发送：

```text
使用 Landscape Agent Pack，先检查本机AutoCAD连接与工具是否可用，不要开始绘图。报告实际状态；失败时保留错误并说明原因。
```

AI 实际回读报告 `backend=com`、`connected=true` 后再开始。连接成功只说明能通信，不代表图纸已验收。失败时打开[故障排查](TROUBLESHOOTING_CN.md)，先保留错误原文。

**AI模型和能操作本机的 Agent 不是一回事。**普通聊天豆包可能只能给建议，不能直接控制本机 AutoCAD。Codex / TRAE 等也要先配置工具，才能实际画图；不能只凭 AI 说“画好了”认定完成。TRAE 的配置模板已提供，当前 RC 未完成该客户端验收。

## 2. 第一次画图

1. 不要拿唯一的正式 DWG 测试。
2. 在文件资源管理器中复制 `A-01.dwg`，将副本改名为 `A-01_AI_TEST.dwg`。
3. 在 AutoCAD 中打开副本，告诉 AI 只处理这张图。
4. 让 AI 先确认文件名、单位和现有实体，再做简单任务。

安装阶段的自动 Smoke Test 与日常画图不同：运行 Smoke Test 前，要自己保存并关闭所有图纸，让 AutoCAD 保持没有打开文档；测试会新建自己的临时文件。日常处理副本时不要运行安装测试，也不要让 AI 关闭其他图纸。

## 3. AI绘图的正确思路

先完整规划 → 确定坐标与尺寸 → 按计划分批画 → 复核结果。

先把入口、道路、功能区等安排说清楚，再执行绘图。通常能减少来回修改、重复对象和等待，也减少 Token 消耗；Token 可以理解为 AI 处理文字的用量。没有必要每画一条线就重新讨论整个设计。

一次给出主要要求。允许 AI 提出常规建议，但建议必须标成假设；没有依据的场地边界、正式尺寸或“不能动”的对象不能猜。

## 4. 新建景观总平面

把方括号内容换成自己的要求，再复制发送：

```text
使用 Landscape Agent Pack 完成任务。
项目：【项目名称】；场地：【尺寸和单位】。
我的想法：【入口、园路、功能、植物或构筑物要求】。
必须保留：【不能动的内容，没有写无】。
最终需要：【总平面DWG及输出位置】。
先规划整体方案并列出假设，等我确认后在测试副本执行。按本Pack规则检查、保存与重开复核，报告实际结果与未验证项。优先完成DWG，不为自动出图无限调试。
```

这些模板是任务指令，不表示整个景观自动设计已稳定。先做小范围测试，通过后再增加内容。

## 5. 修改现有DWG

先打开测试副本，再发送：

```text
使用 Landscape Agent Pack，修改当前测试DWG。
我要修改：【修改内容】；必须保留：【不能动的内容】。
先识别目标，说明调整计划，只改相关对象。修改后检查尺寸和结果，保存前告诉我实际修改了什么，等我确认。
```

确认报告后，再让 AI 保存副本。正式源文件保留原样。

## 6. 检查CAD

```text
使用 Landscape Agent Pack，只读检查当前DWG，先不要修改。
检查图纸组织、重复或异常对象、边界、尺寸文字，以及乔木压园路、越界和园路断路等问题。
依据实际图纸与设计要求，输出问题位置、证据、建议和未验证项目，等我确认再修改。
```

不要把所有开放线都当成错误，也不要把检查请求当作“每项都已支持”的承诺。

## 7. CAD → SketchUp

**可选 / Experimental。**只有你明确要用 SketchUp，并且 AutoCAD、SketchUp / Ringo 已通过你当前机器的环境测试后，才发送下面模板。需要配置时看[可选 Ringo 安装说明](INSTALL_WINDOWS.md#ringo-固定官方版本)。

```text
使用 Landscape Agent Pack，把【测试DWG与建模要求】转换为SketchUp基础模型。
本次明确要求使用可选SketchUp，先检查两端环境，通过后再规划与执行。
保留原CAD和正式模型，依据真实DWG建立有清楚分组的测试模型，避免大面积粘连。保存重开检查尺寸，报告实际完成内容、偏差与未验证项。
```

普通 AutoCAD 任务不需要启动 SketchUp。安装测试显示 `SKIPPED_NOT_RUNNING` 表示跳过未运行的可选组件，不是 AutoCAD 测试失败。

## 8. 如何让AI结果更好

提示词尽量包括六件事：项目类型、场地尺寸、必须出现的内容、不能动的内容、最终文件、验收方式。

过于笼统：“帮我画个漂亮公园”。

更明确：“这是风景园林课程设计，场地30×20m，南侧主入口，保留东侧次入口，主路2m，设置中央休息区、北侧廊架，绿地率不低于45%，输出测试DWG并保存重开验证。”

没有想清楚时，复制[万能模板](../prompts/QUICK_PROMPTS_CN.md#最推荐直接告诉ai你的想法)。让 AI 先列出计划和假设，只核实会影响边界、冻结对象或验收的关键缺项。

## 9. 常见错误不要怎么做

- 不直接改唯一正式 DWG。
- MCP 报错不立即“再画一次”：对象可能已存在。要求使用 Guard 检查新增句柄与几何；`SUCCESS_WITH_FALSE_ERROR` 表示对象已核实创建成功，原错误仍保留。
- Guard 不是原始工具的自动拦截器；AI 必须按[Guard 使用规则](../guards/README.md)调用。重启后也要先查现有对象。
- 不因为 Layout / PDF 问题无限调试，先保存正确 DWG。
- 不一出错就重装 AutoCAD / Python，不随便改注册表。
- 不把普通聊天豆包当作已连接本机工具的 Agent。

## 10. 怎么判断任务真的完成

要求 AI 根据实际文件报告：

```text
使用 Landscape Agent Pack，报告任务验收结果：文件位置、完成内容、实体与图层情况、关键尺寸、保存与重开结果、存在的问题和未验证项目。必须依据实际文件，不能以截图或口头声明代替核查。
```

自己用 AutoCAD 打开交付副本，再核对主要尺寸。报告中的本机路径是供你找到文件用的，公开分享报告前要去掉个人路径和私密配置。
